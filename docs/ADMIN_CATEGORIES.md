# Блок 09 — категории и подкатегории

## Работа владельца

`/admin/categories` показывает дерево, прямое количество связанных товаров,
родителя/уровень, порядок, эффективную видимость и фото. Архивные разделы остаются
в дереве для восстановления. «Додати категорію» открывает форму; название может
автоматически предложить украинский transliteration slug, который можно изменить.
Описание, порядок и видимость редактируются без Git/деплоя. База — единственный
источник дерева меню, мобильной навигации, каталога и хлебных крошек.

Родитель выбирается из дерева: сама категория и потомки исключены. Сервер проверяет
выбор заново; PostgreSQL сериализует изменения дерева и запрещает циклы даже при
прямом обращении к API. Архивного родителя выбрать нельзя. Скрытие родителя скрывает
потомков и фотографии через существующий RLS, не удаляя товары.

Сохранение использует UUID запроса для идемпотентности и updated_at для защиты от
потери чужих изменений. При конфликте нужно обновить страницу и сверить данные.
Кнопка сохранения отключается на время отправки; поля и ошибки сохраняются при отказе.

## Архив и фотографии

Архивирование требует раскрыть предупреждение и подтвердить checkbox. Товары и
product_categories не удаляются. Восстановление возвращает категорию скрытой;
сначала восстановите её родителя, затем при необходимости включите видимость.
Физического удаления категорий в интерфейсе нет.

Фото JPEG/PNG/WebP до **3 MiB** проверяются на сервере по размеру, MIME и magic bytes.
Имя файла генерируется сервером из UUID, исходное имя не используется. Bucket
store-media остаётся приватным, ограничения Storage/RLS из блока 05 действуют.
Форма показывает локальный preview; можно заменить или убрать фото с подтверждением
checkbox. При убирании/замене старый объект сохраняется приватным для безопасного
восстановления, но его прежний URL больше не выдаёт изображение. Очистка неиспользуемых
приватных объектов — отдельная операция владельца; автоматического необратимого удаления нет.

При создании категории с фото сначала резервируется скрытая запись (Storage RLS
требует существующую категорию), затем загружается объект и сохраняются конечные
поля/видимость. Сбой загрузки не публикует пустой раздел: форма даёт ссылку завершить
настройку созданной скрытой категории. SQL и Storage не выдаются за одну транзакцию.

`/category-media/[id]` — anonymous publishable client + RLS; `/admin/category-media/[id]`
— серверная проверка личности и роли, затем JWT администратора. Оба маршрута повторно
проверяют текущий image_path и имеют private/no-store/nosniff. Долгоживущих signed URL
нет, скрытие/архивирование закрывает новое публичное чтение сразу. Уже загруженные
посетителем байты изображения отозвать невозможно.

## Slug и миграция

`20261124000400_admin_categories.sql` применена **только к kos-jeans-dev**.
Добавлены public.category_slug_history (RLS, только SELECT для посетителей) и
private.category_mutations (RLS, собственные административные receipts).
`admin_category_write` — SECURITY INVOKER, каждый вызов проверяет private.is_admin,
права/RLS; не использует service role. Старые slug резервируются за исходной
категорией и ведут на её текущий slug через HTTP 308, сохраняя параметры фильтров.
История скрытых/архивных категорий не читается публично; их старые URL дают 404.
Рекомендация: не удалять историю slug вручную.

Форма использует Server Actions, встроенную проверку Origin Next.js и независимый
requireAdmin на каждой операции. bodySizeLimit 4 MiB; лимит фото 3 MiB ниже лимита
Vercel. Ключи/пароль не логируются; Production намеренно не подключён к dev.

## Проверки

`npm test`: SQL/RLS, циклы, архив без потери ассортимента, optimistic version,
idempotent request, история URL, MIME/signature/validation и существующие регрессии.
`npm run lint`, `npm run typecheck`, `npm run build`.
Живой сценарий Preview: создать явно ТЕСТ-категорию с фото, проверить навигацию и
публичную страницу без деплоя, вложенность, переименование/slug, сортировку, скрытие,
архив и восстановление. Приёмка не заменяется прямым SQL-созданием категории.

Источники: [Next.js Server Actions security](https://nextjs.org/docs/app/guides/data-security),
[Supabase upload](https://supabase.com/docs/reference/javascript/file-buckets-upload).
