## Настройка окружения (уже выполнена для Preview блока 12)

1. Supabase → **kos-jeans-dev** → Settings → API Keys: скопировать Secret key
   формата `sb_secret_…`. Publishable key для этой переменной не подходит.
2. Vercel → kos-jeans → Settings → Environment Variables → добавить
   **SUPABASE_CHECKOUT_SECRET_KEY**. Значение — скопированный Secret key.
3. Выбрать только **Preview**, ограничить Git Branch **feat/block-12-checkout**.
   **Production не выбирать.** Не добавлять префикс NEXT_PUBLIC_.
4. Сохранить и создать новый Preview Deployment: старые сборки не получают новые
   переменные автоматически. Значение в чат не передавать.

секрет уже настроен в игнорируемом `.env.local` с правами 0600, значение не выведено.
Публичный каталог и браузер по-прежнему используют только publishable key и RLS.
Серверный клиент из server-only модуля вызывает только доверенные checkout RPC.

## Процесс

`/cart` проверяет позиции и ведёт на `/checkout`. Форма на украинском: имя/фамилия,
телефон, город, ручной способ Новой пошты (отделение/адрес), адрес и комментарий.
Обзор содержит фотографии, размеры/цвета, количества и текущие цены. Условия
доставки/оплаты не выдуманы: указано, что они требуют решения владельца до запуска.

Строгая серверная валидация нормализует телефон к +380…, ограничивает длины,
перечень способов, 1–50 уникальных вариантов и 1–99 единиц. Итоги из браузера
не принимаются. Переданная цена — только ожидаемая покупателем цена для сверки:
транзакция сравнивает её с заблокированной записью БД, иначе возвращает конфликт.
Интерфейс показывает новые условия и сбрасывает флажок подтверждения.

## Транзакция и идемпотентность

`checkout_submit` доступен только service_role через доверенный сервер, SECURITY
DEFINER с пустым search_path. anon/authenticated не имеют EXECUTE и не пишут orders.
Роль/ключ не передаются браузеру. Сама операция:

- проверяет payload и ключ, вычисляет SHA-256 канонического JSON;
- берёт advisory lock ключа; повтор того же содержимого возвращает прежний результат,
  другое содержимое или другая гостевая сессия дают конфликт;
- берёт guards дерева/каталога, совместимые с админ-редактором, и FOR UPDATE товаров
  и вариантов в стабильном порядке. Категории, публикация, активность, цена и склад
  проверяются после блокировок;
- создаёт header и snapshots order_items, уменьшает каждый конкретный остаток;
- deferred trigger проверяет сумму строк и header; любая ошибка откатывает всё.

Catalog guards сериализуют checkout и изменения каталога в короткой SQL-транзакции.
Это консервативный вариант для v1; внешних запросов внутри транзакции нет. Номера
заказов уникальны, но пропуски sequence при откатах допустимы.

Стабильный UUID запроса хранится в localStorage до подтверждённого результата.
Имена/телефоны/адреса там не хранятся; черновик формы находится только в sessionStorage
и удаляется после успеха. При сбое сети ключ не заменяется. Есть проверка состояния
и повтор того же запроса. Ценовой конфликт не создаёт заказа и требует нового
подтверждения текущих условий с тем же ключом.

После результата из БД purchased-варианты вычитаются из корзины; неотправленные
новые позиции сохраняются. Маркер обработанного ключа записывается атомарно в тот
же localStorage-документ корзины, чтобы повтор восстановления не очищал её дважды.
При невозможности сохранить ключ оформление закрыто до восстановления хранилища.

## Приватность, частота запросов

Гостевая случайная cookie 256 бит: HttpOnly, SameSite=Lax, Secure в Vercel, 7 дней.
БД хранит HMAC с серверным секретом. `/checkout/success` не содержит идентификаторов
или контактов в URL; для просмотра нужны гостевая и receipt cookie. Возвращаются
только номер, сумма и технические ID купленных вариантов, не контактные данные.
Номер заказа сам по себе доступа не даёт; повторное открытие ничего не создаёт.

POST проверяет точный Origin/Host. Тело ограничено 16 КБ. Результаты private/no-store,
noindex/no-referrer. Имена/телефоны/адреса не логируются и не отправляются в кеш.

`checkout_throttle` хранит HMAC ключей в private с RLS, переживает перезапуск
serverless: за 10 минут до 20 запросов сессии, 40 с IP, 200 общих. Учитываются
submit/status; 429 имеет Retry-After. Старые записи убираются после суток. На Vercel
используется перезаписываемый платформой X-Forwarded-For; локально единый test bucket.
[Заголовки Vercel](https://vercel.com/docs/headers/request-headers).

## Проверки и безопасное восстановление тестов

`npm test`, lint, typecheck, build. `npm run checkout:test:hosted -- --dev-only`
проверяет реальную dev-БД через сервер на 3012: создание/повтор, изменение цены,
параллельные запросы последней единицы, ошибку после первого списания, приватность,
RLS и HTTP rate limit. Используются только вымышленные контакты и собственный
маркер запуска. Временный Auth-пользователь обычный, административных ролей нет.

Сценарий сохраняет тестовые заказы как cancelled и восстанавливает их варианты
один раз по inventory_released_at. Новые тестовые товары архивируются, существующие
товары/категории/изображения не удаляются. Это CLI teardown тестов, не функция
управления заказами из блока 13.

Для UI-теста использовать только:
- имя «ТЕСТ Покупець Checkout», телефон +380000000001;
- вымышленный город/отделение;
- комментарий KOS-BLOCK12-UI-LOCAL или KOS-BLOCK12-UI-PREVIEW.

После проверки:
`npm run checkout:cleanup -- --dev-only --marker=KOS-BLOCK12-UI-LOCAL`
(для Preview заменить marker). Сценарий требует точного маркера и обоих тестовых
контактов, берёт те же guards/locks, пропускает уже восстановленные заказы и не
удаляет историю. Повторный запуск не удваивает склад.

Локальный UI уже создал один заказ на 3897 ₴ (26 × 1 и 27 × 2), подтвердил номер,
повторное открытие и пустую корзину; teardown запущен дважды, исходные остатки
3/5/0/2/4 восстановлены. Проверены 320/390/768/1440 без overflow/broken images.
Настоящий Preview-сценарий также пройден на сборке cca7697:
- нехватка stock 27=1 отклонила заказ 27 × 2; после восстановления stock=5 проверка прошла;
- изменение цены 1299 → 1399 ₴ показало новую сумму 4197 ₴ и сбросило согласие;
- после повторного согласия двойное нажатие создало ровно один заказ №12;
- повторное открытие подтверждения не создало дубликат; корзина стала пустой;
- SQL подтвердил 26 × 1 и 27 × 2 по 139900 копеек, совпадение header и суммы строк;
- исходные цена 1299 ₴, остатки 3/5/0/2/4, публикация и пять фото восстановлены;
- точный UI-PREVIEW teardown выполнен дважды: заказ cancelled, склад возвращён один раз;
- форма проверена на 320/390/768/1440 px без горизонтальной прокрутки и сломанных фото,
