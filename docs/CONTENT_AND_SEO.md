Только kos-jeans-dev в local/Preview. Production env не меняется. Индексация закрыта.

## Баннеры

`/admin/banners` → «Додати банер» → создать приватную черновую запись → фото, заголовок,
подзаголовок, alt, текст кнопки, страница магазина, порядок и период → сохранить.
Фото JPEG/PNG/WebP до 3 MiB: MIME и сигнатура проверяются сервером, bucket приватный.
Все ссылки баннера выбираются из страниц/публичных категорий и товаров; SQL повторно
проверяет допустимый маршрут и доступность цели. Внешние URL, javascript:, //, /admin
и произвольные query/path traversal запрещены.

Первый активный баннер — крупный hero с h1, остальные — h2 в порядке sort_order/id.
Нет автопрокрутки, неожиданных переключений или рекламных обещаний. Один широкий
кадр адаптируется по центру; важный объект следует размещать ближе к центру.
Без активных баннеров остаётся нейтральный hero KOS JEANS. Товарные секции сохранены.

Даты вводятся в часовом поясе устройства, сохраняются UTC; список показывает Киев.
Начало включительно, конец исключительно. Архивирование выключает показ, сохраняет
историю и фото. Архивные баннеры доступны только для просмотра администратору.
При замене/снятии фото старые файлы остаются приватными для аудита; постоянная
очистка orphan-файлов не добавлена. Это ограничение хранения, не публичная утечка.

Публичный `/banner-media/[id]` каждый раз проверяет анонимный RLS и текущую связь
с фото; private/no-store/noindex, без signed URL, переживающих скрытие баннера.
Черновые/будущие/истёкшие/скрытые/архивные фото не читаются посетителем.
Приватный `/admin/banner-media/[id]` независимо проверяет Auth и роль.

## Настройки и документы

`/admin/settings`: название, подтверждённые телефон/email и social HTTPS URLs,
описание магазина, доставка, оплата, возвраты, privacy и terms. Только обычный текст,
без HTML. React экранирует содержимое. Ни API-ключи, ни конфигурации сюда не помещать.
Контакты/соцсети публикуются только с отдельным подтверждением владельца; иначе
сохраняются is_public=false и не возвращаются анонимному клиенту.

Все публичные страницы и footer читают свежие разрешённые данные без кеширования.
Черновики документов отображаются с заметной меткой «ЧЕРНЕТКА · НЕ ПОГОДЖЕНО».
`/contacts`, `/delivery`, `/returns`, `/privacy`, `/terms` доступны без регистрации.
Шаблоны не определяют выдуманные реквизиты, сроки, цены доставки или обязанности.

До реального запуска владелец должен предоставить и согласовать:
- официальные наименование/правовой статус продавца, регистрационные и контактные
  данные, реальный телефон/email, адреса для обращений/возвратов при необходимости;
- официальные social URLs и описание магазина;
- способы, географию, стоимость/расчёт и сроки доставки, порядок получения;
- способы и условия оплаты, подтверждения/отмены заказа;
- законные правила обмена/возврата и рассмотрения обращений;
- окончательные terms/privacy: ответственный за данные, основания/цели, получатели,
  сроки хранения, права и контакты по персональным данным. Юридическое согласование
  выполняет владелец с компетентным специалистом; эти черновики его не заменяют.

## Транзакции и безопасность

Миграция `20261125000800_content_seo.sql`: архив баннеров, новые allowlisted ключи
store_settings, private content_requests. `admin_content_write` проверяет реальный
Auth UUID в private.admin_users; grants только authenticated, обычная роль отказана.
Прямые insert/update/delete настроек/баннеров через authenticated отозваны.

Next.js повторно проверяет роль и exact Origin, ограничивает JSON/multipart,
валидирует поля. SQL проверяет поля, целевые URL, существование фото и версию.
Стабильный request UUID + fingerprint защищают повтор; изменённый payload того же
request отклоняется, устаревшая версия даёт понятный конфликт. Guards каталога
согласованы с другими административными операциями. Privileged key админке не нужен.

## SEO и запрет индексации

`src/lib/seo/policy.ts` намеренно возвращает indexingEnabled=false. Ни переменная,
ни Preview URL не включают индексацию автоматически. Для включения после блоков
15–16 потребуется явное разрешение владельца и отдельное изменение с проверками.

- Уникальные title/description, OG/Twitter и canonical для главной, каталога,
  категорий, товаров и информационных страниц. Тексты/названия берутся из Supabase.
- Canonical/OG URL используют только подтверждённый NEXT_PUBLIC_SITE_URL или текущий
  Production https://kos-jeans.vercel.app; не VERCEL_URL и не временный Preview.
- Root meta robots и глобальный X-Robots-Tag: noindex,nofollow.
- robots.txt Disallow: /; sitemap.xml валиден, но пуст до разрешения индексации:
  тестовые товары/Preview URL не публикуются в sitemap.
- Архитектура sitemap готова читать RLS-публичные товары/категории без статического
  ассортимента. Product JSON-LD helper экранирует HTML, не выдумывает offers/reviews/
  ratings; вывод Product сейчас выключен вместе с индексацией, поскольку нет
  реального коммерческого ассортимента. Приватные/admin/receipt страницы не в sitemap.
- Скрытые/архивные товары и категории по-прежнему 404; прежние category slug получают
  существующий безопасный redirect. Неизвестные информационные URL — 404.
