нет тестовой Supabase в Production, оформление и индексация отключены кодом.

## 2. Нужно сделать владельцу вручную

### Обязательные данные перед продажами

Предоставить данные, предназначенные для публикации, согласовать применимость с
юридическим/налоговым специалистом. Пароли и ключи в этот список не входят.

| Сведения | Что подготовить |
| --- | --- |
| Продавец | Юридическое имя/название, регистрационные и налоговые реквизиты, если применимо |
| Связь | Рабочий телефон и email магазина, ответственный за обращения |
| Адрес | Адрес для связи и/или возврата, если требуется |
| Оплата | Реально доступные способы, условия и момент оплаты; онлайн-платежи сейчас не подключены |
| Доставка | Способы, география, стоимость/расчёт, условия и подтверждённые сроки |
| Обмен/возврат | Согласованные правила, порядок обращения, адрес и расходы, с учётом законодательства |
| Персональные данные | Согласованная privacy policy: кто обрабатывает данные, цели, сроки, получатели/сервисы и права покупателя |
| Условия продажи | Согласованные условия заказа, подтверждения, оплаты, исполнения и отмены |
| Ассортимент | Настоящие названия/SKU/описания, состав/характеристики, размеры/цвета, цены/скидки и проверенные остатки |
| Фото | Собственные либо разрешённые фото реальных товаров, права использования и корректные alt |

Незаполненные страницы сейчас честно помечены черновиками. Не заменять отсутствующие
условия выдуманными обещаниями и не начинать продажи по шаблонным текстам.

### Обязательные решения и ручные действия

1. Согласовать подходящие тарифы и допустимые расходы. Vercel Hobby ограничен
   личным некоммерческим использованием; перед продажами проверить фактический тариф
   и условия. Никакой upgrade/платёж автоматически не выполняется.
   [Правила Hobby](https://vercel.com/docs/plans/hobby).
2. Дать отдельное разрешение на создание `kos-jeans-prod`, регион, миграции и
   согласованные Production env. Выполнить план [SUPABASE_PRODUCTION.md](SUPABASE_PRODUCTION.md)
   вместе с Codex. Не переносить dev данные/роли/ключи.
3. Создать собственную production Auth-запись и подтвердить её UUID для роли.
4. Утвердить резервирование PostgreSQL **и Storage**, ответственного и успешную
   репетицию восстановления. Free не даёт права предполагать paid backup/PITR/SLA;
   возможна пауза проекта при низкой активности. Не покупать услуги без решения.
5. Приобрести домен самостоятельно, затем отдельно разрешить подключение/DNS.
   Можно сначала согласовать запуск на Vercel-адресе: собственный домен не является
   техническим обязательством для отключённой безопасной версии.
6. Передать реальные сведения и создать настоящий каталог в нужном окружении;
   не публиковать товар с тестовым stock/фотоиллюстрациями как реальный.
7. Принять будущий PR, который открывает **каталог/админку** только для prod-проекта,
   сохраняя checkout и noindex закрытыми. Сейчас они заблокированы кодом, добавления
   одних переменных недостаточно. Удалить demo-обозначения лишь после реальной готовности.
8. Согласовать отдельную контролируемую приёмку оформления до допуска покупателей.
   Реальные Production заказы во время блока16 не создаются. Проверить суммы,
   последний stock, повтор/таймаут, отмену, отсутствие утечек, поддержку и восстановление.
9. После полного согласования написать **отдельное письменное разрешение на реальные
   заказы**. Разрешение слияния документационного PR16 не заменяет его.
10. Отдельно разрешить индексацию после запуска реального контента; сначала проверить
    canonical/домен/юридические страницы/sitemap и сохранение noindex всех Preview/admin.

История миграций dev: в репозитории9 SQL-файлов, в ledger dev зарегистрированы6;
последние3 были применены SQL в прошлых блоках и проверены тестами. Перед следующим
изменением dev-схемы нужна отдельная сверка/согласование истории; не запускать
повторное применение или migration repair вслепую. Для новой пустой prod-базы
использовать все9 файлов через CLI, не копировать ledger dev. Это не ошибка текущего
Production, который к dev не подключён.

### Необязательные улучшения

Соцсети (только действительные ссылки), собственный домен на раннем этапе,
аналитика/маркетинг после согласования privacy, API Новой почты, онлайн-оплата,
дополнительные языки, улучшения большого каталога. Они не включаются этим блоком.
Отсутствующую соцсеть скрывать; не создавать фиктивные контакты/ссылки.

## 3. Нельзя включать без отдельного разрешения

- [ ] Не создавать prod-проект, не применять к нему SQL и не добавлять Production ключи.
- [ ] Не подключать `kos-jeans-dev` к Production, не переносить тестовые заказы/аккаунты.
- [ ] Не включать реальный checkout/платежи и не списывать реальные остатки.
- [ ] Не разрешать индексацию Production и не индексировать Preview/admin.
- [ ] Не покупать домен, не менять DNS/NS, не активировать платные сервисы/upgrade.
- [ ] Не сливать PR16 в main без отдельного подтверждения. После разрешённого merge
  повторить безопасный Production smoke на новом SHA.

## Порядок перехода и остановки

Безопасный публичный сайт → согласованные данные/бюджет → новая чистая база и backup →
проверенный администратор → закрытая приёмка каталога → согласованная проверка оформления →
письменный допуск реальных заказов → отдельное решение об индексации.

При проблеме держать checkout отключённым и вернуть прошлый проверенный код.
Откат Vercel не отменяет миграции/заказы; базу не откатывать автоматически.
Сначала сохранить данные и согласовать план; не удалять заказы/фото ради исправления.

После блока16 остановиться. Следующая фаза запуска определяется только владельцем.
