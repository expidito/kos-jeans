# KOS JEANS: публикация на Vercel — блок 02

Дата: 2026-11-23 (Europe/Vienna).

## Текущее состояние

PR #1 слит в `main` с явного разрешения владельца. Локальная `main`
синхронизирована с GitHub. Для блока 02 создана отдельная ветка
`feat/block-02-vercel-preview`.

**Публикация заблокирована авторизацией.** Страницы Vercel открыты в Chrome,
но вход не выполнен. Публичного URL, настроенного проекта Vercel и
подтверждённых автоматических deployments пока нет.

## Что сейчас сделать владельцу

Войти в свой аккаунт на [Vercel](https://vercel.com/login) в Chrome и сообщить
Codex «В Vercel вошёл». Можно использовать привычный способ входа;
при входе через GitHub нужен аккаунт `expidito`, которому принадлежит репозиторий.
Пароль, код 2FA и токены вводить только на странице сервиса, не в чате.
Если аккаунта Vercel ещё нет, регистрацию и принятие условий выполняет владелец.
Платный тариф или пробную подписку для этого шага не подключать.

После входа Codex продолжит настройку. Следующие шаги описывают оставшуюся
работу блока, а не уже выполненную интеграцию.

## Импорт репозитория и production

1. Открыть Add New → Project и импортировать
   [expidito/kos-jeans](https://github.com/expidito/kos-jeans).
2. Если Vercel GitHub App не имеет доступа, владелец должен разрешить доступ
   только к `kos-jeans`, проверив запрашиваемые разрешения.
3. Убедиться, что используется существующий репозиторий; не создавать его копию.
4. Framework Preset: Next.js; Root Directory: корень репозитория.
   Node.js: 24.x; Install Command: `npm ci`; Build Command: `npm run build`;
   Output Directory: значение по умолчанию Next.js.
5. Production Branch: `main`. Первую публикацию выполнять из `main`,
   а не из feature-ветки. Проверить SHA исходного коммита deployment.
6. Дождаться Ready и записать точный назначенный адрес `*.vercel.app`.
   Не угадывать адрес по имени проекта.
7. Production URL должен открываться без входа в Vercel. Не менять защиту
   чужих проектов и не публиковать секретные данные ради этой проверки.

## Автоматическая публикация и preview

- В настройках Git подтвердить связь с `expidito/kos-jeans`.
- `main` используется для production; push в feature-ветку/PR — для preview.
- После настройки интеграции отправить изменения блока 02 в отдельную ветку
  и убедиться, что Vercel **автоматически** создал Preview Deployment с тем же SHA.
- Проверить статус Ready и назначенную preview-ссылку. Авторизация для preview
  может зависеть от настроек проекта; это не заменяет публичную production-ссылку.
- В PR должны быть видны результаты проверки Vercel и ссылка на preview.
- Merge PR в `main` выполняется только после подтверждения владельца.

## Переменные окружения

Текущий каркас собирается без ключей и без `.env.local`. Не добавлять пустые
Supabase-ключи в Vercel и не подключать Supabase до блока 05.

После получения реального production-адреса `NEXT_PUBLIC_SITE_URL` можно
задать в Project Settings → Environment Variables для Production.
Для Preview впоследствии используются отдельные значения и тестовая БД.
Изменённые значения применяются при новой сборке/deployment.

Названия будущих переменных перечислены в `.env.example` и README.
`SUPABASE_SERVICE_ROLE_KEY` — исключительно серверный секрет;
не давать ему префикс `NEXT_PUBLIC_` и не коммитить реальные значения.
Файл `.vercel/` исключён из Git.

## Проверки приёмки

- Публичная production-ссылка по HTTPS открывается без авторизации и возвращает 200.
- Отображаются KOS JEANS, украинский текст и пометка «Сайт у розробці».
- Собранный CSS загружается; неизвестный маршрут возвращает украинскую 404.
- Сохраняется `noindex, nofollow` стартовой версии.
- Production связан с `main`; автоматический preview связан с feature-веткой
  и проверенным SHA. Ручная загрузка через CLI не заменяет проверку Git Integration.
- README и PROJECT_PROGRESS содержат реальные ссылки и результаты.
- В GitHub поле Website обновлено действительным production-адресом.

Это ранняя тестовая публикация. Магазин, каталог, админка и заказы ещё не готовы.
Блок 03 не начинается без подтверждения владельца.
