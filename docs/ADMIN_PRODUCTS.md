# Товары, фотографии и склад — блок 10

Окружение: только kos-jeans-dev, local и Vercel Preview. Production не получает
тестовую базу и не открывает административную авторизацию. Используются прежние
две NEXT_PUBLIC_SUPABASE_* переменные, только Preview; новых секретов нет.

## Работа владельца

1. Войти своей постоянной учётной записью в `/admin/login`.
2. «Товари» → «Додати товар»: название, уникальные SKU/slug, описание и состав.
3. Ввести цену в гривнах, например 1499 или 1499,50. Сервер переводит её в целые
   копейки без вычислений с float. Старая цена необязательна и должна быть больше.
4. Выбрать категории из дерева базы. Разрешены несколько назначений. Скрытые
   категории помечены; архивные недоступны для нового назначения.
5. Выбрать до десяти JPEG/PNG/WebP, каждое до 3 МиБ. Можно переставлять, заменять,
   удалять и назначать обложку. У каждого фото есть текстовое описание.
6. Ввести цвет, добавить 26–30, XS–XL или произвольный размер. Проверить отдельные
   SKU и реальные остатки всех вариантов. Нулевой остаток закрывает выбор размера
   в магазине. Существующий вариант выключается без удаления его идентификатора.
7. «Зберегти чернетку» сохраняет незавершённую работу скрытой. Для публикации
   нужны описание, хотя бы одно фото, активный вариант и открытая категория.
8. Выбрать «Опубліковано» и сохранить. Изменения появляются без push/deploy.
   Ссылка «Переглянути в магазині» открывает сохранённый опубликованный товар.
9. Архивирование требует подтверждения: товар и фото исчезают из публичной части,
   категории, варианты и файлы сохраняются. В редакторе можно вернуть статус.

Изменение slug меняет адрес товара; автоматические перенаправления старых product
slug в этом блоке не реализованы. Категории сохраняют свои редиректы блока 09.

## Согласованность и безопасность

- Каждый route handler проверяет точный Origin, Auth getUser и роль из БД.
  Интерфейс не назначает роли и не принимает произвольные Storage paths.
- RPC SECURITY INVOKER проверяют роль независимо от Next.js; RLS остаётся включён.
  Публичные клиенты не получают административных ключей или приватных таблиц.
- В начале нового сохранения резервируется скрытая чернетка со стабильным UUID.
  Затем отдельные запросы загружают фото: фактический прогресс XHR, ограниченный
  размер тела, MIME и сигнатура, SHA-256 и неизменяемый путь из серверной RPC.
- Окончательная RPC сохраняет товар, категории, варианты, порядок и обложку в одной
  транзакции. Ошибка не оставляет частично опубликованный товар. Повторная попытка
  использует тот же request UUID для того же тела; другой payload отклоняется.
- `updated_at` сравнивается на сервере. Изменение дочерних вариантов/фото/связей
  тоже обновляет версию. Устаревшая форма получает конфликт и должна быть сверена
  после обновления страницы; незаметной перезаписи нет.
- Старые файлы попадают в очередь только после успешного сохранения метаданных.
  Удаление выполняется после commit, повторно проверяет отсутствие ссылки, при
  ошибке оставляет очередь для следующего обращения редактора. Незавершённые
  загрузки старше 24 ч также собираются при следующем сохранении/загрузке.
  Постоянный cron не добавлен: без активности очистка ожидает следующего действия.
  Не более 50 ожидающих загрузок на товар; до 20 задач за один проход.
- Черновик после сбоя остаётся в списке товаров. Загруженные, но ещё не привязанные
  фото восстанавливаются повторной попыткой в открытой форме; после закрытия формы
  их нужно выбрать заново. Старые версии остаются доступны до успешного commit.
- Приватные media routes и административный HTML используют private/no-store;
  скрытие публикации закрывает анонимные фото без долгоживущих signed URLs.

Миграция `20261124000500_admin_products.sql`: четыре RPC и три приватные таблицы
журнала запросов, загрузок и очереди очистки. Публичных таблиц не добавлено.
Идентификаторы существующих вариантов сохраняются; удаление товаров физически
не предоставляется. Заказы и корзина в этом блоке не реализованы.

## Проверки

`npm test`, `npm run lint`, `npm run typecheck`, `npm run build`.

`node --env-file=.env.local scripts/test-admin-products-hosted.mjs --dev-only`
проверяет реальную dev-базу и локальный сервер на 3010. Переменная
`PRODUCTS_TEST_BASE` позволяет выбрать проверяемый Preview. Скрипт создаёт только
временного обычного пользователя, удаляет именно его, не назначает admin,
не изменяет существующий ассортимент. Ключи и пароль в отчёт не записываются.
Положительная UI-приёмка выполняется с сессией владельца, без передачи пароля.
