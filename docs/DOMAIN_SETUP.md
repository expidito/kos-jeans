# Домен KOS JEANS: инструкция владельцу

Подготовлено 2026-11-26. **Домен не куплен, DNS не изменён.**
Текущий безопасный адрес: [kos-jeans.vercel.app](https://kos-jeans.vercel.app).
Подключение домена само по себе не включает каталог рабочей БД, заказы или индексацию.

## 1. Выберите имя и зарегистрируйте его самостоятельно

Проверьте написание, доступность имени и условия регистратора: цена продления,
срок регистрации, защита аккаунта и возможность управлять DNS. Убедитесь, что
имя не нарушает чужие права. Аккаунт и подтверждающий email должны принадлежать вам.
Не передавайте пароль регистратора в чат. Покупку и любые платежи выполняете вы;
Codex не покупает домен и не подключает платные услуги без отдельного разрешения.

## 2. Добавьте домен к существующему проекту

После отдельного разрешения на подключение:

1. Откройте [проект kos-jeans в Vercel](https://vercel.com/fedir-team/kos-jeans).
2. Project Settings → Domains → Add Domain. Введите приобретённое имя.
3. Выберите основной адрес: с `www` или без. Оба варианта допустимы; выберите один.
4. Добавьте второй вариант и настройте перенаправление на основной через настройки
   домена Vercel. Проверьте отсутствие циклических перенаправлений.
5. Убедитесь, что домен назначается Production существующего проекта, а не Preview.

## 3. Перенесите только записи, которые покажет Vercel

Откройте DNS у своего регистратора/провайдера. **Точные значения берите из панели
Vercel для вашего домена**, а не из старой статьи или этого документа.

| Что может понадобиться | Для чего | Где взять значение |
| --- | --- | --- |
| A/ALIAS/ANAME, если поддерживается | Основной домен без www | Инструкция Vercel для выбранного DNS-провайдера |
| CNAME | www или другой поддомен | Целевое имя из Vercel |
| TXT | Подтверждение владения, если запрошено | Точная строка из Vercel |
| Nameservers, только если выбран Vercel DNS | Передача обслуживания DNS | Отдельная инструкция Vercel |

Не меняйте NS автоматически. Смена NS требует перенести существующие почтовые MX,
TXT/SPF/DKIM/DMARC и другие нужные записи; иначе может перестать работать почта.
Не удаляйте незнакомые записи и не создавайте конфликтующие записи для того же имени.
Если домен обслуживает почту или другой сайт, сначала согласуйте конкретный план изменений.

Нажмите Refresh/Verify в Vercel. Дождитесь Valid Configuration. Проверяйте результат
на разных устройствах и сетях: распространение зависит от TTL/кешей DNS, точный срок
не гарантируется. При необходимости технический специалист проверяет A/CNAME/TXT через DNS lookup.

## 4. Проверьте HTTPS и перенаправления

После правильного DNS Vercel выпускает сертификат для подключённого домена.
Проверьте основной и альтернативный адреса, HTTP→HTTPS и www→основной вариант.
Не обходите предупреждения браузера о сертификате: вернитесь к проверке DNS/статуса SSL.
Не покупайте отдельный сертификат только ради этой инструкции.
[Официальная инструкция Vercel](https://vercel.com/docs/domains/working-with-domains/add-a-domain).

## 5. Обновите адрес магазина в согласованном выпуске

Попросите Codex подготовить отдельное изменение после подтверждения основного домена:

- `NEXT_PUBLIC_SITE_URL` в Vercel **Production** — новый основной HTTPS origin,
  без пути/параметров. Это публичный адрес, не секрет. После изменения нужен новый deploy.
- Проверить canonical, Open Graph URL/images и внутренние ссылки. Адреса магазина
  формируются из origin в `src/lib/seo/policy.ts`; менять каждый товар вручную не нужно.
- Сохранить noindex, `robots: Disallow: /` и пустой sitemap до отдельного разрешения.
- После отдельного разрешения индексации: изменить код `indexingEnabled()`, проверить
  sitemap с настоящими опубликованными товарами/категориями, исключить admin/cart/checkout,
  сохранить noindex всех Preview. **Сейчас этот переход не реализуется и не включается.**
- Проверить все старые внешние ссылки. Vercel `.vercel.app` останется техническим адресом;
  перенаправление его на основной домен при необходимости готовится отдельным изменением
  с сохранением доступа к защищённым Preview и без redirect loop.

## 6. Настройте Auth только в нужном Supabase-проекте

В будущем `kos-jeans-prod`: Authentication → URL Configuration:
Site URL — основной HTTPS адрес; Redirect URLs — только точные необходимые адреса.
Не добавляйте localhost и общий wildcard Vercel в production-проект.
Тестовые localhost/Preview разрешения относятся только к `kos-jeans-dev`.
[Supabase о redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls).

Текущий вход — серверный email/пароль с возвратом на `/admin` того же сайта.
OAuth/callback и интерфейс восстановления пароля не реализованы: не придумывайте
путь `/auth/callback` как уже работающий. Если они появятся, сначала реализуйте и
проверьте маршруты, затем добавьте точные URL в allowlist и email templates.

## 7. Приёмка после подключения

Откройте на телефоне и компьютере главную, каталог, настоящую категорию/товар,
фото, корзину, информационные страницы и `/admin/login`. Проверьте меню/footer,
прямые ссылки, отсутствующий URL404, вход/выход администратора, HTTPS и canonical.
Настоящие заказы не отправляйте до отдельного письменного разрешения.

Если что-то не работает, сохраните точный адрес и описание ошибки без паролей/ключей.
Не отключайте защиту и noindex ради исправления DNS. Верните согласованную конфигурацию
или прошлую проверенную публикацию, затем повторите проверку.
